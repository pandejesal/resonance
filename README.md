# Resonance - Self-Hosted Music Library

A premium, self-hosted music archival system that prioritizes speed, audio quality, and a beautiful user experience. Built with a Rust backend for maximum performance and a React frontend for a fluid, modern interface.

## Features

- **Bit-perfect playback** - Plays files losslessly and untouched; optional lossy
  transcoding can be enabled in server settings
- **Massive library support** - Handles 500,000+ songs with instant navigation
- **Modern UI** - Glassmorphism, dynamic gradients, 60-120 FPS animations
- **Universal access** - PWA support for Windows, Linux, macOS, Android, iPhone
- **Smart organization** - By artist, album, genre, year, folder, and rating
  (composer/mood/BPM metadata is read when present but not browsable)
- **Instant search** - Results appear while typing across all metadata (FTS5-backed)
- **ReplayGain** - Per-track and per-album LUFS-based gain normalization with
  clipping prevention
- **Gapless playback** - Seamless transitions between tracks
- **Crossfade** - Configurable fade between tracks (1-12 seconds)
- **Equalizer** - 10-band EQ with presets (Rock, Pop, Jazz, etc.) *(Pro tier)*
- **Audio-reactive visualization** - Real frequency data from AnalyserNode
- **Subsonic/OpenSubsonic API** - Stream from any Subsonic client (Symfonium, play:Sub, Amperfy)
- **Smart playlists** - Rule-based playlists ("not played in 30 days", "4★+", genre+year rules)
- **Playlist tools** - Shuffle, sort, dedupe, stats, share, and generate playlists
- **Ratings** - 1-5 star ratings with per-user history
- **Waveform seek bar** - Server-computed visualization of the track's shape
- **Duplicate detection** - Content fingerprinting to find and remove duplicates
- **Multi-room output** - Cast to HTTP targets from the NowPlaying view
- **Real-time sync** - WebSocket push for scan progress and now-playing (via actix-ws)
- **Auto-rescan** - Filesystem watcher detects changes and rescans incrementally (via notify)
- **Touch-optimized** - Swipe navigation and touch-friendly controls
- **Scrobbling** - Last.fm and ListenBrainz integration with retry queue + connection testing
- **Lyrics** - Synced lyrics from LRCLIB with auto-scroll
- **Playlist transfer** - Import playlists from Spotify, YouTube Music, Apple Music,
  SoundCloud; export to CSV, TXT, M3U, or JSON
- **Offline playback** - PWA service worker caching for queue-while-offline
- **Native apps** - Android (JNI), iOS (Tauri), Desktop (Tauri/WebView2)

## Privacy

Your server never phones home. There is no telemetry, and your library, listening
history, ratings, and analytics never leave your machine. The complete, audited list
of every outbound connection the server can make (update check — off by default,
lyrics lookup on demand, license checkout, scrobbling if you enable it, Spotify
import with your own token, LAN casting) lives at
[resonance.app/privacy](https://resonance.app/privacy) — mirroring this repo's
`website/privacy.html`.

## Tech Stack

### Backend
- **Rust** with Actix-web for blazing-fast API
- **SQLite** with WAL mode for efficient database operations
- **lofty-rs** for metadata extraction (bit-perfect)
- **Rayon** for multithreaded parallel scanning
- **Walkdir** for efficient filesystem traversal

### Frontend
- **React 18** with TypeScript for type safety
- **Vite** for instant development and optimized builds
- **Tailwind CSS** for utility-first styling
- **Framer Motion** for buttery-smooth animations
- **Zustand** for lightweight state management
- **React Virtuoso** for virtual scrolling

## Quick Start

### Docker (Recommended)

```bash
# Clone the repository
git clone https://github.com/pandejesal/resonance.git
cd resonance

# Edit docker-compose.yml to mount your music folder
# Update /path/to/your/music to your actual music directory

# Build and start
docker compose -f docker/docker-compose.yml up -d

# Access at http://localhost:8080
```

### Manual Build

#### Prerequisites
- Rust 1.75+
- Node.js 18+
- npm or yarn

#### Backend

cd backend
cargo build --release
./target/release/resonance-backend
```

```

### Installers

Standalone desktop packages for Windows, Linux, and macOS are built from `installer/` and attached to every [GitHub release](https://github.com/pandejesal/resonance/releases) (tag `v*`).

| Platform | Package | Notes |
|----------|---------|-------|
| Windows | `resonance-<version>-windows-setup.exe` | Per-user install, no admin rights needed |
| Linux | `resonance_<version>_amd64.deb` or `resonance-<version>-x86_64.AppImage` | deb for Debian/Ubuntu, AppImage for anything else |
| macOS | `resonance-<version>-macos-<arch>.dmg` (Intel/Apple Silicon) or `.pkg` | Unsigned: right-click → Open on first launch |

The installer runs a small server (default `http://127.0.0.1:8080`) and opens it in an app-mode browser window (Edge/Chrome). Autostart is only registered from a fixed install path — Windows opts in during install; Linux/macOS register on first run when launched from an installed location. Uninstalling never touches your data:

- Windows: data in `%APPDATA%\Resonance` (uninstaller keeps it), autostart via registry `Run` key (hidden window)
- Linux: data in `~/.local/share/resonance`, autostart via `~/.config/autostart` (removed on uninstall)
- macOS: data in `~/Library/Application Support/Resonance`, autostart via a LaunchAgent (only when installed to `/Applications`)

Reinstalling or upgrading keeps your library, settings, and scrobbles.

## Configuration

### Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `RUST_LOG` | `info` | Log level (info, debug, trace) |
| `DATABASE_URL` | Platform data dir | SQLite database path (`%APPDATA%\Resonance` / `~/.local/share/resonance` / `~/Library/Application Support/Resonance`; `RESONANCE_DATA_DIR` overrides) |
| `HOST` | `127.0.0.1` | Server bind address (installers; Docker sets `0.0.0.0`) |
| `PORT` | `8080` | Server port |
| `STATIC_DIR` | next to the binary | Frontend files location (defaults to `<exe>/static` if present, else `./static`) |

### First Launch

1. Open the web interface at `http://localhost:8080`
2. Go to Settings → Add Library
3. Enter a name and the path to your music folder
4. Click "Add Library" then "Scan"
5. Wait for the scan to complete (runs in background)
6. Start browsing and playing your music!

## API Reference

### Auth
- `POST /api/auth/login` - Log in (sets session cookie)
- `POST /api/auth/logout` - Log out
- `GET /api/auth/me` - Get current user
- `POST /api/auth/register` - Register a new user (registration must be enabled)
- `POST /api/auth/guest` - Guest login (if enabled)

### Libraries
- `GET /api/libraries` - List all libraries
- `POST /api/libraries` - Create a library
- `DELETE /api/libraries/:id` - Delete a library
- `POST /api/libraries/:id/scan` - Start scanning
- `GET /api/libraries/:id/scan/progress` - Get scan progress

### Tracks
- `GET /api/tracks` - List tracks (pagination, sorting, filtering, album_id/artist_id/recent)
- `GET /api/tracks/:id` - Get track details
- `PUT /api/tracks/:id` - Update track metadata
- `POST /api/tracks/:id/play` - Record play
- `GET /api/tracks/:id/stream` - Stream audio file
- `GET /api/tracks/:id/artwork` - Get album artwork
- `GET /api/tracks/:id/waveform` - Get waveform peaks (computed + stored on first request)
- `GET /api/tracks/:id/gain` - Get ReplayGain values
- `POST /api/tracks/:id/gain/compute` - Compute + store ReplayGain
- `GET /api/tracks/similar` - Find similar tracks (fingerprint-based)
- `GET /api/tracks/recently-played` - Recently played tracks
- `GET /api/tracks/most-played` - Most played tracks
- `POST /api/tracks/batch-delete` - Delete multiple tracks
- `PUT /api/tracks/batch-rating` - Rate multiple tracks at once
- `GET /api/settings/replaygain` - Get ReplayGain settings
- `PUT /api/settings/replaygain` - Update ReplayGain settings

### Albums & Artists
- `GET /api/albums` - List albums
- `GET /api/artists` - List artists

### Search
- `GET /api/search?q=query` - Search tracks (FTS5), albums, artists, playlists

### Playlists
- `GET /api/playlists` - List playlists
- `POST /api/playlists` - Create playlist
- `DELETE /api/playlists/:id` - Delete playlist
- `GET /api/playlists/:id/tracks` - Get playlist tracks
- `POST /api/playlists/:id/tracks` - Add track to playlist
- `POST /api/playlists/:id/shuffle` - Shuffle playlist
- `POST /api/playlists/:id/sort` - Sort playlist
- `POST /api/playlists/:id/dedupe` - Remove duplicates
- `GET /api/playlists/:id/stats` - Playlist statistics
- `POST /api/playlists/:id/share` - Share playlist
- `POST /api/playlists/generate` - Generate playlist (smart/related tracks)
- `GET /api/playlists/:id/smart/evaluate` - Evaluate smart-playlist rules
- `PUT /api/playlists/:id/smart/rules` - Update smart-playlist rules

### Import & Transfer
- `POST /api/import/preview` - Preview an import (Spotify/YT Music/Apple Music/SoundCloud/M3U/XSPF)
- `POST /api/import/confirm` - Confirm a previewed import
- `GET /api/import/formats` - List import formats
- `POST /api/transfer/export` - Export a playlist (CSV/TXT/M3U/JSON)
- `GET /api/transfer/platforms` - List export platforms

### Settings
- `GET /api/settings/transcode` / `PUT /api/settings/transcode` - Lossy transcoding config
- `GET /api/settings/scrobbling` / `PUT /api/settings/scrobbling` - Scrobbling config
- `POST /api/settings/scrobbling/test` - Test scrobbler connection
- `GET /api/settings/replaygain` / `PUT /api/settings/replaygain` - ReplayGain config

### Statistics
- `GET /api/stats` - Get library statistics
- `GET /api/stats/database` - Get database statistics

### Misc
- `GET /api/health` - Health check
- `GET /api/ws` - WebSocket endpoint

## Performance

- **SQLite WAL mode** for concurrent reads
- **Parallel file scanning** using Rayon thread pool
- **Virtual scrolling** for 500K+ track lists
- **Artwork caching** to disk for instant loading
- **Incremental scanning** - only processes new/changed files
- **Memory-efficient** architecture with streaming

## Security

- **Basic auth** - argon2-hashed passwords, cookie sessions (default admin: `admin`/`admin`, change on first login)
- Per-user playlists, favorites, and listening history
- Rate limiting on auth and license endpoints
- Docker socket access removed from the main compose file (root-equivalent risk documented)
- SQL injection prevention via parameterized queries
